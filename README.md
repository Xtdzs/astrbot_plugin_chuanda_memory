# 串大记忆 · Chuanda Memory

给熟人 QQ 群使用的 AstrBot 记忆插件：按成员 ID 认人，在后台整理人物偏好、近期状态、共同经历和群内梗，回答前自动召回。可以启用“嘴上犀利、本质善良”的串大人格，也可以保留你已有的人格。

**记忆独立于插件代码和聊天会话保存。日常后台更新不发送群消息，不播报“已更新记忆”。**

这是可试用的 v0.2.0。自动化测试覆盖核心、AstrBot 适配层和真实本地 HTTP 服务；尚未完成真实 QQ 群、各类第三方 Agent runner 的端到端联调。

## 安装到 AstrBot

要求：**AstrBot >= 4.24.0，Python >= 3.10**，已配置可用的聊天模型与 QQ 接入。

在 AstrBot 管理面板的插件页，选择通过 GitHub 仓库链接安装：

```text
https://github.com/Xtdzs/astrbot_plugin_chuanda_memory
```

也可以上传 [Releases](https://github.com/Xtdzs/astrbot_plugin_chuanda_memory/releases) 中的插件 ZIP。安装后在插件配置里：

1. `mode` 保持 `local`，即可使用已有 AstrBot 模型后台整理，不需要另开服务。
2. `allowed_groups` 填你们的群 ID。留空表示处理该机器人接收到的全部群。
3. `memory_provider_id` 可留空跟随会话模型，也可以填写已有的便宜模型提供商 ID。
4. 已有自己的人格时关闭 `enable_chuanda_persona`。
5. 群内发送 `/cdmem status` 检查身份与采集状态。

普通聊天开始后，默认等待约20秒批量整理；消息较密集时提前处理。记忆形成后，后续标准 LLM 请求会临时带入相关资料。**不会接管 QQ 发送，也不会主动插话。**

命令前缀以你的 AstrBot 配置为准。机器人只能学习实际到达 AstrBot 的消息；如果 QQ 接入只收到 @消息，就不能学习未收到的其他群聊。

## 能记住什么

| 类型 | 例子 | 规则 |
| --- | --- | --- |
| 人物事实 `fact` | 本人明确说的专业、年级 | 只接受该 ID 本人的消息作为证据 |
| 偏好 `preference` | 喜欢 Rust、希望先给结论 | 允许本人后续纠正同一主题 |
| 边界 `boundary` | 不喜欢某个外号 | 召回优先级高于普通梗 |
| 状态 `state` | 正在准备比赛 | 默认7天，最多30天 |
| 共同事件 `event` | 群友一起赶某次作业 | 默认90天，带实际参与者 ID |
| 群梗 `joke` | “最后一把”的来源和语境 | 默认60天，同一梗默认6小时召回冷却 |

昵称和群名片只是显示信息。身份由平台类型、适配器实例、机器人 ID、成员 ID 共同确定；同名不会合并，改昵称不换人，重置 AstrBot 会话不换人。不同群、不同机器人和私聊默认相互隔离。**同一个人在不同群的档案不会自动共享。**

## 查看、纠正与删除

| 命令 | 行为 |
| --- | --- |
| `/cdmem show` | 查看当前聊天范围内自己的有效人物记忆和编号 |
| `/cdmem group` | 查看当前聊天范围内的共同事件与梗 |
| `/cdmem status` | 查看自己的 ID、范围、记忆数量和采集状态 |
| `/cdmem pause` | 停止在当前范围采集自己的消息，保留已有记忆 |
| `/cdmem resume` | 恢复今后的消息采集，不回补暂停期间消息 |
| `/cdmem forget m_xxx` | 删除一条与自己相关的记忆，阻止同 kind/key 自动重新写入 |
| `/cdmem clear` | 清除当前范围内自己的档案内容、来源消息与相关共同记忆，并暂停采集 |
| `/cdmem help` | 显示命令说明 |

AstrBot 管理员可用 `/cdmem show user_id` 查看当前范围内的档案，也可删除当前范围内的任意记忆。这里的管理员指 AstrBot 管理员权限。

正常聊天中的明确自述、纠正和相处边界由模型在后台提取。需要立即停止采集或删除时使用上面的命令；本版不把任意自然语言“忘了吧”猜成删除指令。

删除会使当前范围内正在处理的旧批次失效，避免后台迟到的结果把内容写回来。删除单条记忆还会去掉其原始证据；同一范围里尚未处理的旧消息会跳过这一批，优先保证遗忘生效。忘掉同一主题后，本版没有自动解除屏蔽功能。

## 本地可读副本与低延迟

v0.2.0 起，记忆数据目录内自动维护三个文件：

```text
memory.sqlite3   # 实际记忆数据库
memory.md        # 人物档案、偏好、共同经历和群梗，直接用编辑器打开
memory.json      # 同一份记忆的结构化查看副本
```

插件和独立服务都使用后台导出线程。SQLite 提交后，消息路径只发一个通知，不等待 Markdown/JSON 渲染或磁盘写入。后台以约0.5秒的窗口合并更新，使用独立 WAL 只读连接取快照，然后在数据库锁之外写文件；文件更新时间还取决于实际磁盘速度。

两个副本使用 UTF-8，按聊天范围和成员 ID 组织，包含来源消息 ID、有效期和屏蔽主题，不复制原始聊天正文。更新、更名、暂停、删除和过期清理都会触发同步。每个文件原子替换；启动时可从已有数据库重建，不要求数据库迁移。正常卸载时会等待最后一次导出完成。

这些文件是查看副本，手动编辑不会回写数据库，也不会被模型当作新记忆。磁盘不可写时保留上次成功副本并记录错误类型，下一次更新或启动重试；两个文件的快照编号可用来核对是否属于同一轮导出。

需要立即重建副本，可在仓库目录执行：

```bash
python -m chuanda_memory export --data-dir /absolute/path/to/memory
```

remote 模式下文件位于**记忆服务机器的数据目录**；容器内通常是 `/data`，从对应持久卷查看。升级后保留原数据目录即可。旧中文命令已统一替换为 `/cdmem` 英文子命令；`/cdmem` 默认显示帮助。

## 记忆与代码分离

默认数据库位置：

```text
AstrBot/data/plugin_data/astrbot_plugin_chuanda_memory/memory.sqlite3
```

也可以设置 `data_dir` 或环境变量 `CHUANDA_MEMORY_DATA_DIR` 为持久磁盘的绝对路径。程序拒绝将数据库放进插件源码目录。容器部署时必须把这个路径对应的 AstrBot `data` 或独立目录挂到持久卷。

升级插件、换模型、新建对话不会主动清除数据库。卸载时不要勾选删除插件数据，也不要删除持久卷。更换适配器实例 ID/机器人账号会进入不同身份命名空间，不会擅自关联旧身份。

数据库 schema 为 v1；遇到更新版本的数据库会拒绝降级读取，不会重建清库。未来 schema 升级应先备份再迁移。备份命令（在仓库目录执行）：

```bash
python -m chuanda_memory backup --data-dir /absolute/path/to/memory
```

备份保存在同一数据目录。删除记忆不会修改历史备份；需要彻底抹除时也要按你的保留策略处理备份与 AstrBot 本身的聊天历史。

原始已处理消息默认保留14天，长期记忆保留精简内容与来源消息 ID。原始内容过期后无法再查看全文依据；失败或待处理任务有独立重试状态，最多自动尝试3次。日志只记录错误类型和计数，不输出群聊正文或模型密钥。

## 独立服务模式

如果希望插件、DSH、其他适配器共用一个独立部署的记忆核心，可运行 HTTP 服务。详见 [部署与接口](docs/service.md)。

```text
QQ → AstrBot 插件 → 独立记忆服务 → 持久 SQLite
                     ↓
               后台模型提取和更新
```

`local` 和 `remote` 使用同一套核心与数据格式。迁移时先停止旧实例，备份并复制整个数据目录，再切换服务地址；**同一个数据库仅运行一个后台整理进程**。多个 AstrBot 客户端可以连接同一个独立服务。

本仓库提供的直接安装入口是 **AstrBot 插件**。DSH 可以通过可信适配器调用相同 HTTP API，但本版不包含 DSH 原生自动挂载包；若你的 DSH 桥接插件绕过 AstrBot 的标准 `on_llm_request`，必须在桥接层接入召回，不能假设会自动注入。

## 当前范围与限制

- 第一版使用按 ID 过滤、中文二元词/英文词匹配、人物偏好优先的检索，没有 embedding 依赖。表达相差很大的旧事件可能漏召回。
- 梗的冷却从“召回进上下文”开始计时，不能证明模型最终一定在回复中用了这个梗。
- 事实与玩笑的语义判断依赖模型。程序可校验证据 ID、主体归属、类型、过期与作用域，不能证明每条自述真实或保证反讽识别完全正确。
- 第一版只处理消息顶层文字，不分析图片、语音、表情包和转发内容，不建立好感度排名或主动发言系统。
- 日常静默更新只是插件不播报记忆动作；生成模型仍可能偶尔主动提到记忆，需要结合你的人格和反馈调节。
- 更换模型不需要重建检索索引。更大数据量、语义召回、人物关系与管理页面可以作为后续版本扩展。

## 开发与验证

```bash
python -m pip install -r requirements.txt
python -m unittest discover -v
python tools/build_release.py
```

测试包括真实 SQLite、真实本地 HTTP 往返，以及明确使用测试替身的 AstrBot adapter 测试；不需要 QQ 账号或付费模型调用。核心测试使用固定结构化模型输出，不能据此宣称真实模型的抽取准确率。

另外可对照固定 AstrBot 源码做静态接口检查：

```bash
python tools/fetch_reference.py
python tools/verify_host_api.py
```
